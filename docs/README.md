# Kites technical documentation

Internal engineering documentation for **Kites (Spatial Image & Manga Translator)**: how the
subsystems work, which contracts are enforced, why the architecture looks like this, and what was
measured when. [doc_guide.md](doc_guide.md) is the rulebook — it defines the five kinds of
documentation, the required depth per layer, and the update rules a change must follow in the same
commit.

## Getting started

Read in this order:

1. [Architecture overview](architecture/overview.md) — MV3 topology, runtime boundaries, storage,
   backend service.
2. [Translation pipeline](architecture/pipeline.md) — OCR → filtering → grouping → inpainting →
   translation → typesetting.
3. [Development setup](development/setup.md) — toolchain, build, loading the extension.
4. [Testing guide](development/testing.md) — what `npm test` proves and what needs a browser.
5. [Coding standards](development/coding-standards.md) and
   [workarounds](development/workarounds.md) — invariants and the upstream bugs they sidestep.

## Reference

- [API reference (generated)](api/index.html) — TypeDoc output for `src/offscreen/**` and
  `src/shared/**`, built from TSDoc with `npm run docs:api`; `docs/api/` is generated and gitignored,
  so build it locally before browsing. `npm run docs:check` fails when the undocumented-symbol count
  grows.
- [Interactive pipeline map](workflow.html) — standalone artifact generated by the Archify compiler
  from [kites-workflow.json](kites-workflow.json); open the HTML directly in a browser, no server.
  The 2026-10-28 regeneration passed artifact checks but still scrolls vertically at every tested
  viewport, so the viewport-fit gates failed; see the
  [browser receipt](dev-history/receipts/workflow.visual-check.json) and
  [screenshot contact sheet](dev-history/receipts/workflow.visual-check.html).

## Development history

[`docs/dev-history/`](dev-history/) is append-only and organised by kind:

- [`devlog/`](dev-history/devlog/) — dated phase logs; the record of what changed and what was
  measured. Start with [how to write a devlog](dev-history/devlog/how_to_write_devlog.md).
- [`plans/`](dev-history/plans/) — finished or superseded implementation plans (bubble detection and
  typesetting upgrade, typesetting/text post-processing, Studio V2 editor port, reader/Studio runtime
  improvement).
- [`audits/`](dev-history/audits/) — dated audits and coverage snapshots
  (community pool, documentation coverage 2026-10-28, UI and UX audits).
- [`research/`](dev-history/research/) — donor and upstream research (Cotrans flow, Kites flow
  snapshot, deep-research reports, ONNX/PaddleOCR investigations).
- [`receipts/`](dev-history/receipts/) — generated validation receipts and screenshots.

Current behaviour is documented in [architecture/](#architecture); a devlog or plan describes the
state at the time it was written and does not override those pages.

[`fullplan.md`](fullplan.md) is the project scope and phase roadmap.
